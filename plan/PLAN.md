# 账号本子：自用版开发计划

## 1. 目标与边界

开发一款仅供个人使用的 Android 账号、密码和双因素认证（2FA）管理应用。重点是本地加密、便捷解锁、受控剪贴板、加密操作日志，以及由用户主动触发的 WebDAV 加密备份。

不做会员、广告、应用账号登录、自建服务器、数据收集、行为分析、静默双向同步或网页自动填充。

## 2. 第一版功能范围

### 账号管理

- 分组与筛选：左栏固定顺序为“默认、动态密码、自定义分组”；所有分组名称均可自定义。
- “默认”和“动态密码”使用稳定的系统标识，名称可改但位置和行为不可改变：默认显示没有任何自定义分组的账号，动态密码显示所有已配置 TOTP 的账号。
- 新建账号时沿用当前选中的普通分组；选中默认时保持未分组，选中动态密码时不建立普通分组关联，只有配置 TOTP 后才进入动态密码分组。
- 用户可新增、改名、删除和拖动排序自定义分组；删除账号最后一个自定义分组后自动回到默认分组。
- 支持长按一个或多个分组做交集筛选（动态密码可与自定义分组组合）；长按账号可选择作为模板新建或复制该账号的全部可复制字段。
- 账号列表、详情、新增、编辑、删除和以既有条目为模板新建。
- 每条账号可有任意数量的自定义字段，例如账号、密码、邮箱、网址、恢复码、备注；编辑页提供“新增字段”和“新增隐藏字段”，已有字段可切换隐藏状态。
- 搜索跨所有账号查找名称、分组和字段内容；后续支持中文、拼音和拼音首字母搜索。
- 复制字段内容；密码和验证码默认在设定时间后自动清除剪贴板。
- 点击账号条目打开底部速览面板，点击面板外空白处或向下滑关闭；不因快速复制而进入详情页。
- 用户名和动态验证码的整行文本及复制按钮均可直接复制。密码默认掩码，点击掩码文本显示明文，点击明文文本复制；密码复制按钮始终直接复制明文。关闭速览后密码恢复掩码。

### 2FA（TOTP）

- 每条账号可保存一个基于时间的一次性密码（TOTP）；如需第二个 2FA，新增独立账号条目保存。
- 支持 6 或 8 位验证码、30 秒等标准周期，以及 SHA-1、SHA-256、SHA-512 算法参数。
- 支持扫描 `otpauth://` 二维码导入和手动输入密钥；导入前展示账号、发行方和参数供用户确认。
- 详情页显示当前验证码、剩余时间和下一周期状态，并可一键复制验证码。
- 恢复码作为普通敏感字段保存；不尝试替用户自动登录或提交验证码。

### 解锁与界面安全

- 首次启动时设置主密码；主密码支持中文、英文、数字和符号。
- 使用主密码或设备已注册的指纹/人脸解锁。
- 进入后台或无操作超过默认 5 分钟时自动锁定；时长可配置。
- 设置安全窗口标记，禁止截图、录屏和最近任务预览显示敏感内容。
- 不设置输错次数限制或故意延迟，保持个人使用时的解锁效率。

### 剪贴板

- 密码和 2FA 验证码复制后默认 30 秒自动清除，时长可手动设置。
- 清除前确认剪贴板仍是本应用复制的同一内容，避免删除用户后来复制的文字。
- 自动清除只处理本应用写入的敏感内容，不读取或记录其他应用的剪贴板内容。

### 安全日志

- 记录账号条目打开、敏感字段复制、2FA 验证码复制、新增/编辑/删除、导入/导出、WebDAV 操作、解锁和自动锁定等事件。
- 每条日志包含时间、事件类型、关联账号的内部 ID 与显示名快照、字段类型、结果和必要的错误类别。
- 绝不写入主密码、密码明文、TOTP 密钥、动态验证码、恢复码、WebDAV 密码或剪贴板文本。
- 日志数据和账号数据使用同一数据加密密钥加密；未解锁时不可读取。
- 设置页可配置保留时长（默认 90 天），可筛选、按账号查看和清空日志；清空操作本身留下不含敏感内容的审计事件。

### 主题

- 设置中提供始终深色、始终浅色、跟随系统；默认始终深色。
- 主题选择持久保存，重启应用后仍保持。
- 界面只使用文字、颜色、Compose 组件和 Material 矢量图标，不引入图片资源。

### 导入、导出与 WebDAV

- 仅支持一种完整加密备份：扩展名为 `.acc`，文件内容为 JSON。
- `.acc` 根节点严格只有两个同级字段：`passwordVault` 和 `appSettings`。不兼容旧版 `ACCOUNTBOX_BACKUP_13` 密文，也不再导出旧版明文格式。
- `passwordVault` 是 Base64 加密数据，内部打包格式版本、KDF 参数、随机盐、随机 IV、认证标签及加密后的自定义分组、账号、自定义字段、隐藏字段标记和单个 TOTP；默认分组和动态密码分组均由账号状态派生，不单独保存。
- `appSettings` 是可读、可手工编辑的软件设置，只保存主题、自动锁定时长、剪贴板清除时长和日志保留期；不做完整性校验。
- 导入自定义 `.acc` 时输入备份主密码；密码库按内容去重而非覆盖：账号名称允许重复，完全相同则跳过，任一内容不同则新增，忽略 `lastEditTime`。软件设置整体替换当前设置，无效或未知设置项忽略。
- 仅保留 `ACCOUNTBOX_JSON_13` 明文账号导入能力；该格式不再作为导出格式，也不支持旧版加密备份导入。
- 支持手动上传加密备份到 WebDAV，以及下载后恢复；按时间命名，例如 `account-2026-08-16.acc`。
- WebDAV 可用于坚果云、NAS、Nextcloud 等兼容服务。
- 备份包含密码库与软件设置；不包含 WebDAV 凭据、设备 Keystore 密钥、生物识别状态或安全日志。

```json
{
  "passwordVault": "Base64 encrypted payload",
  "appSettings": {
    "themeMode": "dark",
    "autoLockSeconds": 300,
    "clipboardClearSeconds": 30,
    "logRetentionDays": 90
  }
}
```

## 3. 技术架构、存储与依赖

### 平台与依赖

- 最低支持 Android 9（API 28），以便直接使用系统的 `PBKDF2WithHmacSHA256`、`AES/GCM/NoPadding`、`GCMParameterSpec` 和 `AndroidKeyStore`；不引入任何第三方加密 JAR。
- 保留 Jetpack Compose、Material 3、Lifecycle 与 Navigation Compose；使用简单的 `AppContainer` 手工组装依赖，不引入 Hilt 或其他依赖注入框架。
- 使用 AndroidX Biometric 提供指纹/人脸认证，DataStore Preferences 保存非敏感软件设置，kotlinx-serialization-json 序列化密码库和 `.acc` 文件。
- 使用 CameraX 和 ML Kit Barcode Scanning 扫描 TOTP 二维码；使用 OkHttp 实现 WebDAV 的连接测试、上传和下载。
- 不使用 Room、SQLite、SQLCipher、Bouncy Castle 或其他数据库/加密库，控制安装包大小。

### 代码结构

```text
com.example.account/
├── app/                 # Application、AppContainer、启动与会话装配
├── core/
│   ├── crypto/          # PBKDF2、AES-GCM、DEK、Keystore、.acc 编解码
│   ├── security/        # 自动锁定、清内存、FLAG_SECURE、生物识别
│   ├── storage/         # 加密文件、AtomicFile、DataStore
│   └── common/          # 时间、结果类型、输入校验
├── data/
│   ├── model/           # PasswordVault、Account、Field、Group、Totp、AuditLog
│   ├── repository/      # VaultRepository、SettingsRepository、BackupRepository
│   ├── backup/          # .acc 与 ACCOUNTBOX_JSON_13 明文导入
│   └── webdav/          # WebDAV 客户端与本机加密凭据
├── feature/             # unlock、accounts、edit、totp、logs、settings、backup
└── ui/                  # navigation、共用 Compose 组件、主题
```

### 本地文件存储

- 密码库不使用数据库。`filesDir/vault.bin` 保存 AES-256-GCM 加密后的完整 `PasswordVault` JSON；其中包含自定义分组、账号、字段、隐藏字段标记、单个 TOTP 与安全日志，默认分组和动态密码分组按账号状态实时派生。
- `filesDir/local-secrets.bin` 使用同一 DEK 加密保存 WebDAV 地址、用户名和应用密码；此文件仅本机使用，绝不进入 `.acc`。
- DataStore Preferences 保存主题、自动锁定、剪贴板清除时长与日志保留期等非敏感设置；导出时组装为 `.acc` 的明文 `appSettings`。
- 每次保存密码库或本机敏感设置时，先完整序列化并加密，再用 `android.util.AtomicFile` 原子替换旧文件；中断写入不破坏现有密码库。
- 解锁后将 `PasswordVault` 解密到内存中完成几百条账号的搜索、筛选、排序和去重；锁定后关闭会话并清除 DEK 与敏感内存引用。

## 4. 加密与数据设计

### 本地数据

1. 首次设置主密码时生成随机 256 位数据加密密钥（DEK）。
2. 主密码以 UTF-8 编码并统一作 NFC Unicode 规范化，兼容中文输入。
3. 每个密码库生成独有随机盐，使用 PBKDF2-HMAC-SHA256 派生密钥加密密钥（KEK）；迭代次数记录在密码库元数据中，并以可接受的设备解锁时间校准。
4. 使用 AES-256-GCM 以 KEK 加密 DEK；账号、自定义分组、单个 2FA 秘钥、隐藏字段标记、设置中的 WebDAV 凭据和安全日志均使用 DEK 加密。导出的 `passwordVault` 另用备份主密码派生的密钥加密。
5. 每次 AES-GCM 加密使用新的随机 IV 并校验认证标签；发现篡改即拒绝读取。
6. TOTP 仅在已解锁的内存会话中按 RFC 6238 计算；锁定时清除内存中的 DEK、密钥和明文数据。

### 生物识别解锁

- 使用 Android Keystore 中不可导出的 AES 密钥加密同一个 DEK。
- 该 Keystore 密钥要求每次使用时完成指纹或人脸认证。
- 生物识别密钥仅当前设备可用；换设备、重装应用或生物识别凭据失效时，使用主密码解锁后重新启用。

### WebDAV 与备份

- WebDAV 仅保存加密备份，不上传明文账号数据。
- 备份使用独立的随机盐和 IV；新设备通过主密码解密，不能依赖旧设备 Keystore 密钥。
- WebDAV 地址、用户名和应用密码仅加密保存在本机，绝不写入备份文件。
- 禁用 Android 自动备份，避免系统备份产生不受本应用控制的数据副本。

## 5. 页面规划

页面结构与交互细节见 [FRONTEND_DESIGN.md](FRONTEND_DESIGN.md)。

1. 解锁页：主密码输入、指纹/人脸解锁。
2. 首页：左侧纵向分组、右侧账号列表、字母索引、搜索、新增和更多菜单。
3. 分组管理页：默认/动态密码名称修改，以及自定义分组的新增、改名、删除与拖动排序。
4. 账号速览面板：快速复制字段与 2FA；点击空白处或下滑关闭。
5. 账号详情页：字段和 2FA 验证码，不展示操作日志。
6. 账号编辑页：新增、修改、排序、删除字段，新增隐藏字段及单个 2FA。
7. 扫码导入页：扫描或确认 TOTP 配置。
8. 安全日志页：筛选和查看本机操作记录。
9. 设置页：安全、剪贴板、主题、日志、导入导出和 WebDAV。
10. 备份与 WebDAV 页：完整 `.acc` 加密备份恢复、旧版 v13 明文账号导入、连接配置、测试连接和手动上传下载。

## 6. 实施顺序

1. 建立 Compose 应用框架、导航、主题和前端设计中的基础组件。
2. 实现安全窗口、自动锁定、主密码与生物识别解锁。
3. 接入本地加密数据层，建立账号、字段、分组、TOTP 和审计日志的数据模型。
4. 完成默认/自定义分组与字段的账号管理、跨账号搜索、按当前分组新建、模板新建和随机密码。
5. 实现 TOTP 计算、二维码扫描导入、验证码展示与受控复制。
6. 实现剪贴板定时清除和安全日志写入、查询、保留与清空。
7. 完成加密导入导出。
8. 完成 WebDAV 手动备份与恢复。
9. 在真机验证全部安全与恢复流程。

## 7. 验收标准

- 未解锁时不能读取任何账号、TOTP 或日志内容。
- 指纹和正确主密码均可解锁；中文主密码可正常创建和解锁。
- TOTP 与主流验证器在相同时间、密钥和参数下生成相同验证码；二维码导入后参数正确保存。
- 截屏、录屏和最近任务预览不显示账号内容。
- 已复制的密码或验证码会在设定时间后清除，且不会误清除后续复制的内容。
- 日志准确记录打开和复制的账号/字段类型，但数据库、备份和界面日志均不含任何敏感值明文。
- 本地 `vault.bin` 和 `.acc` 中的 `passwordVault` 均不能以明文直接读取；`.acc` 根节点只包含 `passwordVault` 和 `appSettings`。
- 可从 WebDAV 下载加密备份，并用主密码在另一台设备恢复账号、2FA 和软件设置；WebDAV、设备生物识别与日志保持本机原状。
- 错误主密码、Base64 损坏或认证标签校验失败时，拒绝导入密码库；手工修改有效的 `appSettings` 后可正常应用设置。
- 所有分组均可改名；默认和动态密码改名后仍保持固定位置及系统行为。
- 从自定义分组新建账号会自动加入该分组；从默认分组新建账号保持未分组；从动态密码分组新建账号只有在配置 TOTP 后才显示在该分组。
- 删除账号最后一个自定义分组后，账号显示在默认分组；动态密码与自定义分组组合筛选时返回交集结果。
